# Python `__init__.py`

> **`__init__.py`는 이 디렉터리를 하나의 Python 패키지로 취급하도록 구성하고, 패키지가 import될 때 실행할 초기화 코드를 작성할 수 있는 파일이다.**

여기서 **초기화(initialization)** 란
**패키지를 import하면서 필요한 준비 작업을 하는 것** 을 의미한다.

Python 3.3부터는 `__init__.py`가 없어도 **네임스페이스 패키지** 를 구성할 수 있기 때문에, 현재는 단순히 "패키지임을 표시하는 파일"이라고만 이해하기보다는 **패키지가 import될 때 실행되는 초기화 모듈** 이라고 이해하는 것이 좋다.

## `__init__.py`의 주요 역할

### 1. 패키지가 import될 때 실행할 코드를 작성

다음과 같은 패키지가 있다고 가정한다.

```text
calc/
├── __init__.py
├── add.py
└── sub.py
```

`__init__.py`에 다음과 같이 작성할 수 있다.

```python
print("calc 패키지가 import되었습니다.")
```

그리고 다른 파일에서:

```python
import calc
```

를 실행하면 `calc` 패키지가 import되는 과정에서 `calc/__init__.py`가 실행된다.

```text
import calc
    ↓
calc 패키지 탐색
    ↓
calc/__init__.py 실행
    ↓
calc 패키지 사용
```

따라서 `__init__.py`에는 패키지를 사용하기 전에 필요한 **초기화 작업** 을 작성할 수 있다.

---

### 2. 패키지의 기능을 편리하게 사용할 수 있도록 구성

예를 들어 `add.py`에 다음 함수가 있다고 하자.

```python
def add(a, b):
    return a + b
```

`__init__.py`에서:

```python
from .add import add
```

라고 작성하면 사용자는 다음과 같이 간단하게 가져올 수 있다.

```python
from calc import add

print(add(10, 20))
```

원래는 다음과 같이 작성해야 한다.

```python
from calc.add import add
```

여기서 `.`은 **현재 패키지** 를 의미한다.

```python
from .add import add
```

→ 현재 패키지(`calc`)의 `add.py`에서 `add`를 가져온다.

---

### 3. 패키지의 공개 인터페이스를 관리

패키지 내부에는 여러 모듈과 함수가 존재할 수 있다.

```text
calc/
├── __init__.py
├── add.py
├── sub.py
├── multiply.py
└── _internal.py
```

이 중에서 사용자에게 제공하고 싶은 기능만 `__init__.py`에서 가져올 수 있다.

```python
from .add import add
from .sub import sub
from .multiply import multiply
```

그러면 사용자는 패키지 내부의 구체적인 파일 구조를 알 필요 없이:

```python
from calc import add, sub, multiply
```

처럼 사용할 수 있다.

즉, `__init__.py`를 이용하면 **패키지 내부 구조를 어느 정도 숨기면서 외부에 제공할 기능을 정리할 수 있다.**

---

## `__name__`으로 실행 확인하기

`__init__.py`에서도 `__name__`을 사용할 수 있다.

`calc/__init__.py`:

```python
print(__name__)
```

다른 파일에서:

```python
import calc
```

를 실행하면:

```text
calc
```

가 출력된다.

`__init__.py`가 `calc` 패키지의 일부로 import되었기 때문에 `__name__`의 값이 `calc`가 되는 것이다.

---

## 일반 패키지와 네임스페이스 패키지

### 일반 패키지

```text
calc/
├── __init__.py
├── add.py
└── sub.py
```

`__init__.py`가 존재한다.

### 네임스페이스 패키지

```text
calc/
├── add.py
└── sub.py
```

`__init__.py`가 없어도 Python의 import 시스템을 통해 패키지처럼 사용할 수 있다.

따라서:

```text
__init__.py 존재
    ↓
일반 패키지

__init__.py 없음
    ↓
네임스페이스 패키지가 될 수 있음
```

이라고 이해할 수 있다.

단, **`__init__.py`가 없다고 무조건 네임스페이스 패키지라는 의미는 아니다.**

---

### 정리

`__init__.py`의 핵심 역할은 다음과 같다.

1. **이 디렉터리를 일반 Python 패키지로 구성할 수 있다.**
2. **패키지가 import될 때 실행할 초기화 코드를 작성할 수 있다.**
3. **패키지의 기능을 사용하기 편하게 구성할 수 있다.**
4. **패키지의 공개 인터페이스를 관리할 수 있다.**
5. **패키지 수준의 변수나 설정 등을 정의할 수 있다.**

> **`__init__.py` = 패키지가 import될 때 실행되는 초기화 모듈이며, 패키지의 외부 인터페이스를 구성하는 데 사용할 수 있는 파일**

## 일반 패키지와 Namespace Package

Python의 패키지는 크게 **일반 패키지(Regular Package)**와 **Namespace Package**로 나눌 수 있다.

### 1. 일반 패키지 (Regular Package)

* `__init__.py` 파일이 존재한다.
* 패키지가 `import`될 때 `__init__.py`가 실행된다.
* `__init__.py`에 패키지의 초기화 작업을 작성할 수 있다.

```text
calc/
├── __init__.py
├── add.py
└── sub.py
```

> **초기화** = 패키지를 import하면서 필요한 준비 작업을 하는 것

### 2. Namespace Package

* `__init__.py` 파일이 없어도 패키지로 사용할 수 있다.
* 하나의 패키지를 여러 디렉터리에 나누어 구성할 수 있다.
* 서로 다른 디렉터리에 **같은 패키지 이름**을 사용할 수 있다.
* 서로 다른 경로에 있는 같은 이름의 패키지를 하나의 패키지처럼 사용할 수 있다.
* 단, 해당 디렉터리가 Python의 모듈 검색 경로(`sys.path`)에 포함되어 있어야 한다.

```text
경로 A/
└── mypackage/
    └── a.py

경로 B/
└── mypackage/
    └── b.py
```

이 경우 `A`와 `B`가 서로 다른 위치에 있어도 `mypackage`라는 동일한 패키지 이름을 사용할 수 있다.

```python
import mypackage.a
import mypackage.b
```

### 핵심 차이

| 구분               | 일반 패키지       | Namespace Package     |
| ---------------- | ------------ | --------------------- |
| `__init__.py`    | 존재함          | 없어도 됨                 |
| `__init__.py` 실행 | O            | X                     |
| 초기화 코드           | 작성 가능        | 작성할 `__init__.py`가 없음 |
| 여러 디렉터리에 분산      | 일반적으로 X      | O                     |
| 같은 패키지 이름 사용     | 일반적으로 하나의 위치 | 여러 위치에서 가능            |

## Python 모듈 검색 경로와 환경변수

Python에서 다른 디렉터리에 있는 모듈이나 패키지를 `import`하려면 해당 모듈의 경로가 **Python의 모듈 검색 경로(`sys.path`)**에 포함되어 있어야 한다.

### 1. 같은 상위 폴더에 있는 경우

```text
project/
├── A/
│   └── a.py
└── B/
    └── b.py
```

`project`에서 실행하면 일반적으로 `project`가 `sys.path`에 포함된다.

따라서 Python은 `A`와 `B`를 찾을 수 있으므로 별도의 환경변수 설정이 필요하지 않다.

```python
import A.a
import B.b
```

### 2. 서로 다른 상위 폴더에 있는 경우

```text
project_A/
└── A/
    └── a.py

project_B/
└── B/
    └── b.py
```

`project_A`에서 실행하면 기본적으로 Python은 `project_B`의 위치를 알지 못할 수 있다.

```text
project_A  ← 현재 검색 가능한 경로
project_B  ← 검색 경로에 없음
```

이때 `project_B`를 Python의 검색 경로에 추가하면 `B`의 모듈을 `import`할 수 있다.

대표적인 방법이 `PYTHONPATH` 환경변수를 사용하는 것이다.

```bash
export PYTHONPATH="/경로/project_B"
```

그러면 Python의 검색 경로에 `project_B`가 추가되어 다음과 같이 사용할 수 있다.

```python
import B.b
```

### 핵심

> **상위 폴더가 같은지 여부 자체가 중요한 것이 아니라, 모듈이 들어 있는 디렉터리의 상위 경로가 `sys.path`에 포함되어 있는지가 중요하다.**

* 같은 상위 폴더 → 해당 상위 폴더가 `sys.path`에 있다면 별도 설정 없이 import 가능
* 다른 상위 폴더 → 해당 경로가 `sys.path`에 없다면 `PYTHONPATH` 등을 이용해 검색 경로를 추가할 수 있음
