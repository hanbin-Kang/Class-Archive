## 3. import 시 모듈 탐색 순서

`import`를 사용하면 Python은 모듈을 찾기 위해 정해진 경로를 순서대로 탐색한다.

1. **현재 실행 환경의 경로**

   * 정확히는 `sys.path`의 첫 번째 항목
   * 일반적으로 실행한 스크립트가 있는 디렉토리 등이 포함된다.

2. **`PYTHONPATH`**

   * 환경변수에 등록된 모듈 탐색 경로

3. **Python 표준 라이브러리**

   * Python에 기본적으로 포함되어 있는 모듈

4. **`site-packages`**

   * `pip`로 설치한 외부 패키지가 저장되는 곳

## 4. `__name__`

`__name__`은 Python에서 제공하는 **매직 변수**로, 현재 모듈이 어떤 이름으로 실행되고 있는지를 나타낸다.

### 직접 실행하는 경우

파일을 직접 실행하면 해당 파일이 프로그램의 시작점이 되므로:

```python
print(__name__)
```

출력 결과:

```text
__main__
```

즉,

```python
__name__ == "__main__"
```

이 된다.

### 다른 파일에서 import하는 경우

다른 파일에서 해당 모듈을 `import`하면 그 파일은 프로그램의 시작점이 아니라 **모듈로 사용**된다.

예를 들어 `calc.py`를 import하면:

```python
__name__ == "calc"
```

가 된다.

따라서 다음과 같은 코드를 사용하면 해당 파일이 직접 실행될 때만 특정 코드를 실행할 수 있다.

```python
if __name__ == "__main__":
    ...
```

# 5. `__init__.py`

`__init__.py`는 패키지를 구성할 때 사용되는 파일이다.

`__init__.py`의 존재 여부에 따라 일반 패키지(Regular Package)와 Namespace Package를 구분할 수 있다.

### 일반 패키지

패키지 디렉토리 안에 `__init__.py`가 존재한다.

```text
gsc/
├── __init__.py
└── calc.py
```

`import gsc`를 하면 `__init__.py`의 코드가 실행된다.

따라서 `__init__.py`에 변수나 함수를 정의하면:

```python
# __init__.py

name = "Hanbin"

def hello():
    print("Hello")
```

다른 파일에서:

```python
import gsc

print(gsc.name)
gsc.hello()
```

처럼 사용할 수 있다.

### Namespace Package

`__init__.py`가 없어도 특정 조건을 만족하면 패키지로 사용할 수 있다.

```text
gsc/
└── calc.py
```

이 경우 `gsc`는 Namespace Package로 인식될 수 있다.

Namespace Package는 여러 디렉토리에 걸쳐 하나의 패키지처럼 구성할 수도 있다.

---

# 6. `import gsc`와 패키지 객체

`import gsc`를 하면 Python은 `gsc`를 Python에서 사용할 수 있는 **패키지 객체**로 만들어 관리한다.

예를 들어:

```text
project/
├── main.py
└── gsc/
    └── calc.py
```

`gsc` 안에 `__init__.py`가 없는 상태에서:

```python
import gsc
```

를 실행하면 Python은 `gsc`를 Namespace Package로 인식하고 `gsc`라는 패키지 객체를 만든다.

`__init__.py`가 없기 때문에 패키지를 초기화하면서 실행할 코드가 없으므로, 이를 쉽게 **"빈*객체처럼 보인다"**고 표현할 수 있다.

하지만 실제로 완전히 아무것도 없는 것은 아니다. 패키지의 위치와 같은 정보는 가지고 있다.

반대로 `__init__.py`가 존재하면 일반 패키지로 인식되고, `import gsc`를 하는 과정에서 `__init__.py`가 실행된다.

# 7. 패키지 내부의 하위 모듈

`import gsc`를 했다고 해서 `gsc` 내부의 모든 파일을 자동으로 찾아서 실행하는 것은 아니다.

예를 들어:

```text
gsc/
├── __init__.py
├── calc.py
└── test.py
```

에서:

```python
import gsc
```

를 실행하면 `gsc` 패키지와 `__init__.py`가 처리되지만, `calc.py`와 `test.py`가 자동으로 실행되는 것은 아니다.

하위 모듈을 사용하려면 직접 import해야 한다.

```python
import gsc.calc
```

또는:

```python
from gsc import calc
```

---

# 8. `__init__.py`에서 하위 모듈 import하기

`__init__.py`에서 하위 모듈을 직접 import하도록 작성할 수도 있다.

예를 들어:

```text
gsc/
├── __init__.py
└── calc.py
```

`__init__.py`에:

```python
from . import calc
```

를 작성하면 된다.

여기서 `.`은 **현재 패키지**를 의미한다.

따라서:

```python
from . import calc
```

는

> 현재 패키지 안에 있는 `calc` 모듈을 가져와라.

라는 의미이다.

이렇게 설정하면 다른 파일에서:

```python
import gsc
```

만 해도 `__init__.py`가 실행되면서 `calc`가 함께 import되므로:

```python
gsc.calc
```

형태로 사용할 수 있다.

## 핵심 정리

```text
import gsc
    ↓
gsc 패키지를 찾음
    ↓
┌──────────────────────────────┐
│ __init__.py가 있는 경우         
│ → 일반 패키지                   
│ → __init__.py 실행            
└──────────────────────────────┘

┌──────────────────────────────┐
│ __init__.py가 없는 경우       
│ → Namespace Package          
│ → 초기화 코드 없음                
└──────────────────────────────┘
```

그리고 패키지 내부의 하위 모듈은 자동으로 전부 import되지 않는다.

```python
import gsc
```

→ `gsc` 패키지를 import

```python
import gsc.calc
```

→ `gsc` 패키지의 `calc` 모듈까지 import

또는 `__init__.py`에서:

```python
from . import calc
```

→ `import gsc`만 해도 `calc`를 함께 import하도록 설정 가능

### 핵심 개념   

> **`import`는 지정한 모듈이나 패키지를 가져오는 것이며, 패키지 내부의 하위 모듈까지 자동으로 전부 탐색하고 실행하는 것은 아니다.**
>
> **`__init__.py`는 패키지가 import될 때 실행되는 초기화 파일이며, 하위 모듈을 import하여 패키지 외부에서 사용할 수 있도록 구성할 수도 있다.**
