# Linux 파일 권한

## 1. Linux에서 사용자와 파일 권한이 필요한 이유

Linux는 여러 사용자가 동시에 사용할 수 있는 **다중 사용자 운영체제**이다.

여러 사용자가 같은 디렉토리와 파일에 접근할 수 있기 때문에, 권한이 없다면 다른 사용자가 내 파일을 수정하거나 삭제할 수 있다.

따라서 Linux에서는 파일과 디렉토리에 대해 **누가 무엇을 할 수 있는지 권한을 설정**한다.

---

## 2. 사용자(User)와 그룹(Group)

### 사용자(User)

Linux에서는 각각의 사용자를 구분한다.

각 사용자는 고유한 사용자 ID(User ID)를 가진다.

파일에는 해당 파일을 소유한 **소유자(Owner)** 가 존재한다.

### 그룹(Group)

여러 사용자를 하나의 그룹으로 묶을 수 있다.

그룹을 사용하면 여러 사용자에게 동일한 권한을 부여할 수 있다.

파일 권한은 크게 다음 3개의 대상에게 적용된다.

| 대상 | 의미 |
|---|---|
| Owner | 파일의 소유자 |
| Group | 파일이 속한 그룹 |
| Others | 소유자와 그룹에 속하지 않는 나머지 사용자 |

각 대상마다 `r`, `w`, `x` 권한을 따로 설정할 수 있다.

---

## 3. `ls -l`로 파일 권한 확인하기

`ls -l`을 사용하면 파일의 상세 정보를 확인할 수 있다.

    ls -l

예:

    -rw-r--r-- 1 hanbin hanbin 12 Oct 2 15:12 test.txt

각 부분은 다음과 같다.

    -rw-r--r-- 1 hanbin hanbin 12 Oct 2 15:12 test.txt
    │         │ │      │      │  │        │
    │         │ │      │      │  │        └─ 파일 이름
    │         │ │      │      │  └──────── 수정 시간
    │         │ │      │      └─────────── 파일 크기
    │         │ │      └────────────────── 그룹
    │         │ └───────────────────────── 소유자
    │         └─────────────────────────── 하드 링크 수
    └───────────────────────────────────── 파일 종류 + 권한

### 첫 번째 문자

첫 번째 문자는 파일의 종류를 나타낸다.

| 문자 | 의미 |
|---|---|
| `-` | 일반 파일 |
| `d` | 디렉토리 |

예:

    -rw-r--r-- → 일반 파일
    drwxr-xr-x → 디렉토리

---

## 4. `r`, `w`, `x` 권한

Linux의 기본 권한은 다음 3가지이다.

| 권한 | 의미 |
|---|---|
| `r` | read → 읽기 |
| `w` | write → 쓰기 |
| `x` | execute → 실행 |

권한이 없으면 `-`로 표시한다.

예:

    rwx
    rw-
    r--
    ---

---

## 5. Owner / Group / Others

예를 들어 다음과 같은 권한이 있다고 하자.

    -rw-r--r--

권한 부분만 보면:

    rw- r-- r--
    │   │   │
    │   │   └─ Others
    │   └───── Group
    └───────── Owner

따라서:

    rw- → Owner
    r-- → Group
    r-- → Others

즉 `rw-r--r--`는 다음과 같다.

| 대상 | 권한 |
|---|---|
| Owner | `rw-` |
| Group | `r--` |
| Others | `r--` |

---

# 6. 일반 파일과 디렉토리의 `r/w/x` 차이

`r`, `w`, `x`라는 문자는 같지만 **일반 파일과 디렉토리에서 실제 의미가 다르다.**

| 권한 | 일반 파일 | 디렉토리 |
|---|---|---|
| `r` | 파일 내용 읽기 | 내부 이름 목록 확인 |
| `w` | 파일 내용 수정 | 파일/디렉토리 생성·삭제·이름 변경 |
| `x` | 파일 실행 | 내부 접근·이동 |

이 차이를 반드시 구분해야 한다.

---

# 7. 일반 파일의 권한

## `r` - 읽기

파일의 내용을 읽을 수 있다.

    cat test.txt

파일에 `r` 권한이 없다면 파일 내용을 읽을 수 없다.

---

## `w` - 쓰기

파일의 내용을 수정할 수 있다.

    echo "hello" > test.txt

또는:

    printf "hello\n" >> test.txt

파일에 `w` 권한이 없다면 파일 내용을 수정할 수 없다.

---

## `x` - 실행

파일을 프로그램처럼 실행할 수 있다.

예를 들어 쉘 스크립트가 있다면:

    ./hello.sh

파일에 실행 권한이 없다면 직접 실행할 수 없다.

---

# 8. 디렉토리의 권한

디렉토리에서는 `r/w/x`의 의미가 일반 파일과 다르다.

## `r` - 내부 이름 목록 확인

디렉토리 안에 어떤 파일과 디렉토리가 있는지 이름을 확인할 수 있다.

    ls docs

하지만 `r`만 있다고 해서 내부 파일에 접근할 수 있는 것은 아니다.

---

## `w` - 내부 항목 관리

디렉토리에 `w` 권한이 있으면 내부의 파일이나 디렉토리를 생성·삭제·이름 변경할 수 있다.

단, 실제로 이러한 작업을 하려면 일반적으로 `x` 권한도 필요하다.

    w + x
    ↓
    파일/디렉토리 생성
    파일/디렉토리 삭제
    파일/디렉토리 이름 변경

---

## `x` - 디렉토리 내부 접근

디렉토리의 `x`는 **디렉토리 내부에 접근하거나 경로를 통해 내부 파일에 접근할 수 있는 권한**이다.

예:

    cd docs

또는:

    cat docs/report.txt

내부 파일의 이름을 알고 있다면 `x` 권한을 이용하여 접근할 수 있다.

---

# 9. 디렉토리 권한 조합

## `r--`

    r--

가능:

    ls docs

디렉토리 내부의 **이름 목록은 확인할 수 있다.**

하지만 `x`가 없기 때문에 내부 파일에 접근하거나 디렉토리 안으로 이동할 수 없다.

    cat docs/report.txt

→ Permission denied

    cd docs

→ Permission denied

즉:

    r--
    ↓
    이름 목록 확인 가능
    내부 접근 불가능

---

## `--x`

    --x

디렉토리 내부의 파일 이름 목록은 확인할 수 없다.

    ls docs

→ Permission denied

하지만 파일 이름을 알고 있다면 접근할 수 있다.

    cat docs/report.txt

→ 파일 내용 접근 가능

또한:

    cd docs
    cd ..

와 같이 디렉토리 내부로 이동할 수 있다.

즉:

    --x
    ↓
    목록 확인 불가능
    알고 있는 파일에 접근 가능
    디렉토리 이동 가능

---

## `r-x`

    r-x

가능:

    ls docs
    cd docs
    cat docs/report.txt

즉:

- 목록 확인 가능
- 내부 접근 가능
- 경로를 통한 파일 접근 가능

하지만 `w`가 없기 때문에 디렉토리 내부의 항목을 생성·삭제·이름 변경할 수 없다.

예:

    touch docs/new.txt

→ Permission denied

정리하면:

    r-x
    │││
    ││└─ x → 접근 가능
    │└── w 없음 → 생성/삭제/이름 변경 불가능
    └─── r → 목록 확인 가능

---

## `rwx`

    rwx

가장 많은 권한을 가진 상태이다.

가능:

- 내부 목록 확인
- 내부 접근
- 파일/디렉토리 생성
- 파일/디렉토리 삭제
- 파일/디렉토리 이름 변경

예:

    touch docs/new.txt
    mv docs/new.txt docs/renamed.txt
    rm docs/renamed.txt

---

# 10. 디렉토리의 `r`과 `x`는 별개이다

디렉토리의 `r`은 **목록을 확인하는 권한**이고, `x`는 **내부에 접근하는 권한**이다.

따라서:

    r--
    ↓
    목록은 볼 수 있지만 내부 접근은 불가능

    --x
    ↓
    목록은 볼 수 없지만 알고 있는 경로로 접근 가능

    r-x
    ↓
    목록 확인 + 내부 접근 가능

---

# 11. 부모 디렉토리의 `x` 권한

디렉토리 내부의 파일을 경로를 통해 접근하려면 **파일 자체의 권한뿐만 아니라 경로에 포함된 디렉토리의 `x` 권한도 필요하다.**

예:

    docs/
    └── report.txt

다음 명령을 실행한다고 하자.

    cat docs/report.txt

이때:

    docs/
      ↓
    x 권한 필요

    report.txt
      ↓
    파일 자체의 r 권한 필요

즉 파일에 `r`이 있다고 해서 무조건 읽을 수 있는 것이 아니다.

**부모 디렉토리에도 경로를 통과할 수 있는 `x` 권한이 필요하다.**

---

# 12. 파일 삭제와 파일의 `w` 권한

중요한 점:

**파일을 삭제할 때 파일 자체의 `w` 권한이 필요한 것은 아니다.**

파일 삭제는 해당 파일이 들어 있는 **부모 디렉토리의 권한**에 의해 결정된다.

예:

    docs/
    └── remove-me.txt

`remove-me.txt`가 다음과 같이 읽기 전용이어도:

    r--

부모 디렉토리에 `w + x` 권한이 있다면 파일을 삭제할 수 있다.

    rm docs/remove-me.txt

즉:

    파일 내용 수정
    → 파일 자체의 w 권한

    파일 삭제
    → 부모 디렉토리의 w + x 권한

---

# 13. 숫자로 표현하는 권한

Linux에서는 `r/w/x`를 숫자로 표현할 수도 있다.

기본 값은 다음과 같다.

    ┌─────┬─────┬─────┐
    │  r  │  w  │  x  │
    │  4  │  2  │  1  │
    │ 2²  │ 2¹  │ 2⁰  │
    └─────┴─────┴─────┘

각 권한은 2의 거듭제곱으로 표현된다.

    r = 2² = 4
    w = 2¹ = 2
    x = 2⁰ = 1

따라서:

    rwx
    ↓
    4 + 2 + 1
    ↓
    7

---

# 14. 숫자 권한 조합

권한은 필요한 것만 더해서 표현한다.

    r-- = 4
    -w- = 2
    --x = 1

    rw- = 4 + 2 = 6
    r-x = 4 + 1 = 5
    -wx = 2 + 1 = 3
    rwx = 4 + 2 + 1 = 7
    --- = 0

표로 정리하면:

| 문자 | 숫자 |
|---|---:|
| `---` | 0 |
| `--x` | 1 |
| `-w-` | 2 |
| `-wx` | 3 |
| `r--` | 4 |
| `r-x` | 5 |
| `rw-` | 6 |
| `rwx` | 7 |

---

# 15. `chmod 644` 이해하기

예를 들어:

    chmod 644 test.txt

`644`는 3개의 권한 그룹으로 나누어 해석한다.

    6   4   4
    │   │   │
    │   │   └─ Others
    │   └───── Group
    └───────── Owner

각 숫자를 다시 권한으로 바꾸면:

    6 = 4 + 2 = rw-
    4 = r--
    4 = r--

따라서:

    644
    ↓
    rw-r--r--

즉:

    Owner  → rw-
    Group  → r--
    Others → r--

---

# 16. 자주 사용하는 숫자 권한

    600 → rw-------
    644 → rw-r--r--
    700 → rwx------
    755 → rwxr-xr-x
    777 → rwxrwxrwx

예를 들어 `700`은:

    7 = rwx
    0 = ---
    0 = ---

따라서:

    700
    ↓
    rwx------

소유자만 읽기·쓰기·실행이 가능하다.

---

# 17. `chmod` 명령어

파일이나 디렉토리의 권한을 변경할 때 `chmod`를 사용한다.

기본 형식:

    chmod 권한 파일

예:

    chmod 644 app.conf

또는 기호를 사용할 수 있다.

    chmod u-w app.conf

---

# 18. `chmod` 기호

### 대상

| 기호 | 의미 |
|---|---|
| `u` | User → Owner |
| `g` | Group |
| `o` | Others |
| `a` | All → 모두 |

### 연산

| 기호 | 의미 |
|---|---|
| `+` | 권한 추가 |
| `-` | 권한 제거 |
| `=` | 권한 지정 |

### 권한

| 기호 | 의미 |
|---|---|
| `r` | 읽기 |
| `w` | 쓰기 |
| `x` | 실행 |

---

# 19. `chmod` 기호 방식 예시

Owner의 쓰기 권한 제거:

    chmod u-w app.conf

Owner의 쓰기 권한 추가:

    chmod u+w app.conf

Owner에게 실행 권한 추가:

    chmod u+x hello.sh

Group의 읽기 권한 제거:

    chmod g-r test.txt

Others의 쓰기 권한 제거:

    chmod o-w test.txt

---

# 20. 파일 쓰기 권한 실습

기존 파일의 내용을 확인한다.

    cat app.conf

Owner의 쓰기 권한을 제거한다.

    chmod u-w app.conf

읽기는 여전히 가능하다.

    cat app.conf

하지만 파일에 내용을 추가하려고 하면:

    printf 'theme=dark\n' >> app.conf

Permission denied가 발생한다.

다시 쓰기 권한을 추가한다.

    chmod u+w app.conf

이제 다시 추가할 수 있다.

    printf 'theme=dark\n' >> app.conf

마지막 줄을 확인한다.

    tail -n 1 app.conf

결과:

    theme=dark

---

# 21. 실행 권한 실습

쉘 스크립트를 만든다.

    printf '#!/bin/bash\necho Hello_Linux\n' > hello.sh

권한을 `644`로 설정한다.

    chmod 644 hello.sh

실행한다.

    ./hello.sh

실행 권한이 없기 때문에:

    Permission denied

Owner에게 실행 권한을 추가한다.

    chmod u+x hello.sh

다시 실행한다.

    ./hello.sh

결과:

    Hello_Linux

---

# 22. `./`의 의미

다음 명령어에서:

    ./hello.sh

`./`는 **현재 디렉토리**를 의미한다.

즉:

    ./hello.sh
    ↓
    현재 디렉토리에 있는 hello.sh

그리고 `hello.sh`를 직접 실행하기 위해서는 실행 권한 `x`가 필요하다.

---

# 23. `bash hello.sh`와 `./hello.sh`의 차이

다음 두 명령은 실행 방식이 다르다.

    ./hello.sh

이 방식은 `hello.sh` 파일 자체에 실행 권한 `x`가 필요하다.

반면:

    bash hello.sh

이 방식은 `bash` 프로그램에게 `hello.sh`를 읽어서 실행하도록 하는 방식이다.

따라서 두 방식은 같은 것이 아니다.

---

# 24. `#!/bin/bash`

쉘 스크립트의 첫 줄에:

    #!/bin/bash

를 작성할 수 있다.

이것은 해당 스크립트를 실행할 때 사용할 인터프리터를 지정하는 역할을 한다.

# 25. 디렉토리 권한 실습 준비

실습 디렉토리로 이동한다.

    cd ~/linux-lab/permission-lab

`docs` 디렉토리를 만든다.

    mkdir -p docs

파일을 만든다.

    printf 'hello\n' > docs/report.txt

파일 권한을 설정한다.

    chmod 600 docs/report.txt

디렉토리 권한을 설정한다.

    chmod 700 docs

권한을 확인한다.

    ls -ld docs
    ls -l docs/report.txt

결과적으로:

    docs       → rwx------
    report.txt → rw-------

---

# 26. 디렉토리 `r--` 실습

디렉토리의 권한을 `r--`로 변경한다.

    chmod 400 docs

목록을 확인한다.

    ls -1 --color=never docs

파일 이름은 확인할 수 있다.

하지만 `x`가 없기 때문에 내부 파일에 접근할 수 없다.

    cat docs/report.txt

→ Permission denied

또한:

    cd docs

→ Permission denied

정리:

    r--
    ↓
    이름 목록 확인 가능
    내부 접근 불가능

다시 복구한다.

    chmod 700 docs

---

# 27. 디렉토리 `--x` 실습

디렉토리 권한을 `--x`로 변경한다.

    chmod 100 docs

목록을 확인하면:

    ls -1 --color=never docs

→ Permission denied

하지만 파일 이름을 알고 있다면:

    cat docs/report.txt

파일에 접근할 수 있다.

또한:

    cd docs
    cd ..

와 같이 디렉토리 내부로 이동할 수 있다.

정리:

    --x
    ↓
    목록 확인 불가능
    알고 있는 파일에 접근 가능
    디렉토리 이동 가능

# 28. 디렉토리 `r-x` 실습

디렉토리 권한을 `r-x`로 설정한다.

    chmod 500 docs

목록 확인:

    ls docs

가능하다.

파일 접근도 가능하다.

    cat docs/report.txt

하지만 파일을 새로 만들 수는 없다.

    touch docs/new.txt

→ Permission denied

이유:

    r-x
    │││
    ││└─ x → 접근 가능
    │└── w 없음 → 생성/삭제/이름 변경 불가능
    └─── r → 목록 확인 가능

# 29. 디렉토리 `rwx` 실습

디렉토리에 `rwx` 권한을 부여한다.

    chmod 700 docs

이제 파일을 만들 수 있다.

    touch docs/new.txt

이름을 변경할 수도 있다.

    mv docs/new.txt docs/renamed.txt

삭제할 수도 있다.

    rm docs/renamed.txt

즉:

    rwx
    ↓
    목록 확인
    내부 접근
    생성
    삭제
    이름 변경

# 30. 디렉토리 `w`와 파일 `w`는 다르다

다음 상황을 생각해보자.

    docs/
    └── report.txt

`docs`의 권한이:

    r-x

이고 `report.txt`의 권한이:

    rw-

라면?

`docs`에는 `w`가 없지만 `report.txt` 자체에는 `w`가 있다.

따라서 기존 파일의 내용을 수정할 수 있다.

    printf 'added\n' >> docs/report.txt

확인:

    cat docs/report.txt

결과:

    hello
    added

즉:

    디렉토리의 w
    → 디렉토리 내부 항목을 생성/삭제/이름 변경

    파일의 w
    → 파일 내용 수정

둘은 서로 다른 역할이다.

# 31. 읽기 전용 파일 삭제 실습

디렉토리의 권한을 먼저 설정한다.

    chmod 700 docs

파일을 만든다.

    printf 'temporary\n' > docs/remove-me.txt

파일을 읽기 전용으로 만든다.

    chmod 400 docs/remove-me.txt

파일 자체에는 `w`가 없다.

하지만 부모 디렉토리인 `docs`에는 `rwx`가 있다.

따라서:

    rm -i docs/remove-me.txt

삭제할 수 있다.

확인:

    ls docs

`remove-me.txt`가 사라진 것을 확인할 수 있다.

핵심:

    파일의 w
    → 파일 내용 수정 권한

    부모 디렉토리의 w + x
    → 파일 이름을 삭제할 수 있는 권한

# 32. 전체 권한 구조

Linux 권한은 다음 구조로 이해하면 된다.

    파일 권한
        │
        ├── Owner
        │     └── rwx
        │
        ├── Group
        │     └── rwx
        │
        └── Others
              └── rwx

예:

    -rwxr-xr--

    rwx → Owner
    r-x → Group
    r-- → Others

# 33. 숫자 권한 핵심

    ┌─────┬─────┬─────┐
    │  r  │  w  │  x  │
    │  4  │  2  │  1  │
    │ 2²  │ 2¹  │ 2⁰  │
    └─────┴─────┴─────┘

    r = 2² = 4
    w = 2¹ = 2
    x = 2⁰ = 1

따라서:

    rwx
    ↓
    4 + 2 + 1
    ↓
    7

예:

    rw- = 4 + 2 = 6
    r-x = 4 + 1 = 5
    r-- = 4
    -wx = 2 + 1 = 3

# 34. 파일과 디렉토리 권한 비교

| 권한 | 일반 파일 | 디렉토리 |
|---|---|---|
| `r` | 파일 내용 읽기 | 내부 이름 목록 확인 |
| `w` | 파일 내용 수정 | 생성·삭제·이름 변경 |
| `x` | 파일 실행 | 내부 접근·이동 |

가장 중요한 차이:

    파일
    r → 내용 읽기
    w → 내용 수정
    x → 실행

    디렉토리
    r → 내부 이름 목록 확인
    w → 내부 항목 관리
    x → 내부 접근·이동

# 35. 권한 실습 핵심 정리

## 파일

    r → 파일 내용 읽기
    w → 파일 내용 수정
    x → 파일 실행

## 디렉토리

    r → 내부 이름 목록 확인
    w → 파일/디렉토리 생성·삭제·이름 변경
    x → 내부 접근·이동

## 권한 숫자

    r = 4
    w = 2
    x = 1

## 권한 조합

    7 = rwx
    6 = rw-
    5 = r-x
    4 = r--
    3 = -wx
    2 = -w-
    1 = --x
    0 = ---

## 권한 대상

    u = Owner
    g = Group
    o = Others
    a = All

## `chmod`

    chmod u+w 파일
    chmod u-w 파일
    chmod u+x 파일
    chmod 644 파일
    chmod 700 디렉토리

# 36. 반드시 기억할 핵심

### 1. 권한은 누구에게 적용되는가?

    Owner / Group / Others

### 2. 기본 권한은 무엇인가?

    r = read
    w = write
    x = execute

### 3. 숫자 권한은 왜 4, 2, 1인가?

    r = 2² = 4
    w = 2¹ = 2
    x = 2⁰ = 1

따라서:

    rwx = 4 + 2 + 1 = 7

### 4. `644`는 무엇인가?

    644
    ↓
    rw-r--r--

    Owner  → rw-
    Group  → r--
    Others → r--

### 5. 파일과 디렉토리에서 `r/w/x`의 의미는 무엇인가?

    파일
    r → 내용 읽기
    w → 내용 수정
    x → 실행

    디렉토리
    r → 내부 목록 확인
    w → 생성/삭제/이름 변경
    x → 내부 접근/이동

### 6. 디렉토리의 `r`과 `x`는 다르다.

    r--
    → 목록 확인 가능
    → 내부 접근 불가능

    --x
    → 목록 확인 불가능
    → 알고 있는 경로로 접근 가능

    r-x
    → 목록 확인 가능
    → 내부 접근 가능
    → 생성/삭제/이름 변경 불가능

    rwx
    → 목록 확인 가능
    → 내부 접근 가능
    → 생성/삭제/이름 변경 가능

### 7. 파일 삭제에는 파일 자체의 `w`가 필요하지 않다.

    파일 내용 수정
    → 파일 자체의 w

    파일 삭제
    → 부모 디렉토리의 w + x

### 8. 경로를 통한 파일 접근에는 부모 디렉토리의 `x`가 필요하다.

    cat docs/report.txt

    docs/
    → x 필요

    report.txt
    → 파일 자체의 r 필요
