# 2026-09-03 Java 수업 정리

## 1. Java 명명 규칙 (Naming Conventions)

Java 코드의 가독성과 일관성을 위한 명명 관례입니다.

* **클래스명 (Class Name)**: 첫 글자는 **대문자**로 시작합니다. (PascalCase)
  * 예: `Student`, `MyClass`
* **변수명 / 메서드명 (Variable & Method Name)**: 첫 글자는 **소문자**로 시작하며, 단어가 바뀔 때 대문자를 사용합니다. (camelCase)
  * 예: `studentName`, `calculateScore()`

## 2. 연산자 (Operators)

### 2.1 산술 및 대입 연산자
* `+`, `-`, `*`, `/` : 기본 사칙연산
* `++` / `--` : 증감 연산자
  * `x++;` $\rightarrow$ `x = x + 1;`
  * `x--;` $\rightarrow$ `x = x - 1;`
* `+=` / `-=` : 복합 대입 연산자
  * `x += 10;` $\rightarrow$ `x = x + 10;`

### 2.2 논리 및 비교 연산자
* `==` (같다), `!=` (다르다)
* **AND 연산 (`&` vs `&&`)**: 모든 조건이 `true`여야 함
  * `&` : 앞의 조건이 `false`여도 **뒤의 조건을 끝까지 확인**함.
  * `&&` : 앞의 조건이 `false`이면 **뒤의 조건은 확인하지 않고 넘어감** (Short-circuit).
* **OR 연산 (`|` vs `||`)**: 하나라도 `true`면 만족함
  * `|` : 앞의 조건이 `true`여도 **뒤의 조건을 끝까지 확인**함.
  * `||` : 앞의 조건이 `true`이면 **뒤의 조건은 확인하지 않고 넘어감** (Short-circuit).

## 3. 제어문 (Control Flow)

### 3.1 `if` 문
Java의 `if`문에서는 범위 비교 시 연속 비교(`80 < score <= 90`)가 불가능하므로, **반드시 논리 연산자(`&&`)를 사용**해야 합니다.

```java
// 올바른 범위 비교 예시
if (80 < score && score <= 90) {
    System.out.println("B학점");
}
```


## 4. Java vs. Python 메모리 관리 동작 원리 (변수의 수명과 저장 방식)

이 문서는 **Java**와 **Python** 두 언어가 함수(메서드) 내부에서 선언된 변수를 메모리에서 어떻게 다루는지, 특히 "임시성"과 "저장 위치"를 중심으로 비교 설명합니다.

---

### 핵심 요약 (Summary)

| 특징 | **Java (지역 원시 타입)** | **Python (모든 변수)** |
|:--- |:--- |:--- |
| **철학** | 타입 기반의 강력한 효율성 | "Every is an Object" (일관성) |
| **스택(Stack) 저장값** | **실제 값** 그 자체 (데이터값) | 힙에 있는 **객체의 메모리 주소(참조)** |
| **힙(Heap) 저장 객체** | 없음 (지역 원시 타입인 경우) | **모든 값** (정수, 문자열 등) |
| **변수 복사 (`b = a`)** | 스택에 있는 실제 값이 복사됨 (서로 독립) | 스택에 있는 주소가 복사됨 (동일 객체 참조) |
| **수명 (임시성)** | 함수 종료 시 스택에서 즉시 파괴 | 스택의 주소는 즉시 파괴, **힙 객체는 GC가 수거** |

---

### 시각적 메모리 모델 비교 (Visual Memory Models)

두 언어의 함수 `test()` 내에서 `a = 10;`과 `b = a;`가 실행되었을 때의 메모리 상태를 시각화했습니다.

### 1. Java의 메모리 모델 (원시 타입 vs 참조 타입)

Java는 변수를 선언할 때 선언한 명확한 자료형(Data Type)에 따라 메모리 저장 방식이 달라집니다.

* **원시 타입 (`int x = 10;`)**
  스택(Stack) 영역에 변수 `x`와 실제 값 `10`이 함께 저장되며, 힙(Heap) 영역에는 아무것도 저장되지 않습니다. 
  Java는 기본적으로 변수를 **값을 직접 담는 상자**로 취급합니다.

* **참조 타입 (`Integer x = new Integer(10);`)**
  스택(Stack) 영역에는 변수 `x`에 **힙 객체의 메모리 주소값**이 저장되고, 힙(Heap) 영역에는 실제 **정수 객체 `10`** 이 생성되어 저장됩니다.


### 2. Python의 메모리 모델 (참조)

`x = 10`을 예시로 들면, 변수 `x`는 스택(Stack) 영역에 `x = (Heap에 10이 저장된 메모리 주소값)`으로 저장되고, 힙(Heap) 영역에는 실제 **정수 객체 `10`** 이 저장됩니다.

Python은 변수를 **힙 객체를 가리키는 포스트잇(이름표)**으로 취급하며, 모든 데이터는 힙 메모리에 존재합니다.

### 핵심 결론

* **Python**: 변수의 **'실제 값'이 스택에 저장되는 경우는 없습니다.** 모든 데이터가 객체이므로 스택에는 오직 **힙(Heap) 객체의 메모리 주소값(참조)**만 저장됩니다.
* **Java**: **원시 타입(Primitive Type)인 경우에만** 스택에 변수의 **'실제 값'**이 직접 저장됩니다.

---

### 메모리 저장 방식 비교

| 구분 | Java (원시 타입) | Python (모든 타입) |
| :--- | :--- | :--- |
| **선언 예시** | `int x = 10;` | `x = 10` |
| **스택(Stack) 저장 내용** | 실제 데이터 값 (`10`) | 힙 객체의 메모리 주소값 |
| **힙(Heap) 저장 내용** | 없음 | 정수 객체 (`10`) |
| **값 저장 방식** | 변수 상자 안에 **값 직접 저장** | 변수에 **힙 객체 주소표 부착** |

### 상세 동작 설명 (Detailed Analysis)

### 1. Java: 스택에 값을 담는 임시 변수

`public void test() { int a = 10; ... }`

Java는 메모리 효율성과 실행 속도를 매우 중요하게 생각합니다. 따라서, 함수(메서드) 호출 시 스택 프레임에 공간을 만들고, 원시 타입(`int`, `boolean` 등)의 **실제 데이터값(`10`)을 그 공간에 즉시 집어넣습니다.**

*   **동작:** `int b = a;`를 하면 `a` 상자 속 10을 복사해 `b` 상자에 담습니다. 둘은 완벽히 분리됩니다.
*   **소멸:** 함수가 종료되면 스택 프레임 전체가 메모리에서 사라지므로, 그 안에 담긴 원시값 10들도 **별도의 과정 없이 즉시 파괴** 됩니다. 가장 빠른 소멸 방식입니다.
*   **결론:** 스택에 직접 값을 담는 **진짜 임시 데이터** 입니다.

### 2. Python: 힙에 있는 객체를 가리키는 이름표

`def test(): a = 10; ...`

Python은 일관성을 중요하게 생각합니다. "모든 것이 객체"이므로, 숫자 10조차 **힙 메모리에 `int` 타입의 객체** 로 생성됩니다. 함수 실행 시 스택에는 이 객체의 **메모리 주소값(참조)** 만 잠깐 보관됩니다.

*   **동작:** `b = a`를 하면 `a`가 가리키던 10 객체의 주소를 `b`도 똑같이 가리키게 합니다. (객체 공유)
*   **소멸:** 함수가 종료되면 스택에 있던 주소(이름표 `a`, `b`)는 즉시 파괴됩니다. 하지만 **힙에 있는 실제 객체 `10`은 여전히 메모리에 남습니다.**
*   **Garbage Collection:** Python은 힙 객체의 "참조 카운트"를 확인합니다. 함수 종료로 인해 `10` 객체를 가리키는 주소(참조)가 0이 되면, Python의 GC가 나중에 이를 수거해 갑니다.
*   **결론:** 스택의 **이름표는 임시** 지만, 실제 **값 객체는 GC에 의해 소멸하는 힙 데이터** 입니다.

### 중요한 예외 (Critical Exceptions)

*   **Java의 모든 변수가 스택은 아니다:** Java에서도 클래스의 필드(멤버 변수)로 선언된 원시 타입은 객체에 속하므로 **힙(Heap)** 에 저장됩니다. (객체가 파괴될 때까지 유지)
*   **정적 변수(Static):** 클래스의 `static` 변수는 별도의 영역(Metaspace)에 저장되어 프로그램 종료 시까지 살아남습니다.
